# 🤸 Ragdoll Playground

A browser-based ragdoll physics sandbox. Pick an everyday location (stairs, pyramid, rooftop, skate park…),
drop a ragdoll human or a pile of blocks into it, and hit it with snowballs, air pressure, shoves and shockwaves.
Describe any new location in the chat and **Claude Opus 5.5** (via the GitHub Copilot SDK) builds it for you.

- **Frontend:** vanilla JavaScript ES modules (no build step, no TypeScript), [three.js](https://threejs.org) for rendering
- **Physics:** [cannon-es](https://pmndrs.github.io/cannon-es/) — pure JS rigid bodies with cone-twist joints for the ragdoll
- **Backend:** Node.js + Express, [`@github/copilot-sdk`](https://www.npmjs.com/package/@github/copilot-sdk) for scene generation

## Getting started

```bash
npm install
npm run build      # pre-generates the 10 built-in scenes into data/presets
npm start          # http://localhost:3000
```

The scene designer chat is **off by default**. Enable it with `ENABLE_CHAT=true` on a machine where GitHub
Copilot is available; it uses your GitHub Copilot sign-in (same as the Copilot CLI) and is only shown if
Copilot starts and reports a signed-in user. Override the model with `COPILOT_MODEL=<model-id>`
(default `claude-opus-5.5`) and the port with `PORT`.

```powershell
$env:ENABLE_CHAT = "true"; npm start   # bash: ENABLE_CHAT=true npm start
```

## Using it

| Control | Action |
| --- | --- |
| Left click | Use the selected tool |
| `W` `A` `S` `D` / arrow keys | Walk the camera forward / left / back / right (`Shift` = faster) |
| `Q` / `E` | Turn the view left / right around the look-at point |
| `T` / `G` | Tilt the view up / down |
| `Z` / `X` | Move the camera down / up (never below the ground) |
| `+` / `-` or mouse wheel | Zoom in / out |
| Right drag | Look around (orbit) |
| Middle drag or `Ctrl` + right drag | Pan |
| Camera panel | Front / Back / Left / Right / Top / Low-angle views, scene view, focus ragdoll |
| `F` / `C` | Toggle follow-the-ragdoll camera / focus the latest ragdoll |
| `1`–`8` | Select tool (Place, Push, Snowball, Bowling ball, Air blower, Shockwave, Grab, Camera) |
| `N` / `K` | Drop a ragdoll at the scene's spawn point / kick the latest ragdoll |
| `Space` / `Backspace` | Pause / reset scene |

**Items:** ragdoll human (limp), balancing human, crate pyramid, block tower, dominoes, beach ball, barrel stack, snowman.

**Balancing human:** stands on its own like a person. Its joints are held in a standing pose by lock
constraints ("muscles") and an ankle-strategy balance controller tilts the body back over its feet after a
disturbance. The controller only works while the feet are planted and the centre of mass is above them, so small
pushes make it sway and recover, while a hard shove, a heavy hit or being swept off its feet makes it lose balance
and go limp like a ragdoll (a "💫 Human lost balance!" toast appears). A settled human sleeps, so it stands
perfectly still until something touches it. Without gravity (Zero-G, Black hole) there is nothing to stand on, so
it floats limp.

**Forces:** push (impulse), snowball & bowling ball (projectiles with ballistic aiming), air blower (cone of
air pressure while held), shockwave (radial explosion), grab & drag (spring constraint), global wind.

**Physics modes:** Realistic, Arcade (bouncy, 2.5× forces), Moon, Zero-G, Black hole (orbiting attractor),
Bouncy castle — plus a time-scale slider for slow motion.

## Scenes

- `data/presets/` — 10 built-in everyday locations generated by `npm run build` from
  [`scripts/build-presets.js`](scripts/build-presets.js). `npm run build:ai` instead asks the model to design them.
- `data/scenes/` — every scene generated from the chat. Scenes are **append-only**: files are written with the
  `wx` flag and there is no delete API, so previously generated scenes can always be reloaded from the sidebar.

The scene JSON format (boxes, spheres, cylinders, ramps, staircases, quarter pipes, dynamic props and pre-placed
items) is documented and validated in [`public/js/shared/scene-format.js`](public/js/shared/scene-format.js).
All model output is sanitized/clamped by `normalizeScene` before it is stored.

## Deploying to Azure App Service

[`deploy-to-azure.ps1`](deploy-to-azure.ps1) deploys to an existing Linux Node.js App Service (PowerShell 7 +
Azure CLI, after `az login`). It regenerates the presets, runs the tests, zips the app (without `node_modules`)
and deploys it with `az webapp deploy`. It sets `SCM_DO_BUILD_DURING_DEPLOYMENT=true` and
`CUSTOM_BUILD_COMMAND=npm install --omit=dev` so production dependencies are installed on App Service,
`NODE_ENV=production`, and `ENABLE_CHAT=false` because GitHub Copilot is not available there.
The app runs at <https://ragdoll.jannemattila.com> (App Service managed certificate).

```powershell
.\deploy-to-azure.ps1 -AppName "ragdoll" -ResourceGroup "rg-app-services" -WhatIf   # validate only
.\deploy-to-azure.ps1 -AppName "ragdoll" -ResourceGroup "rg-app-services"
```

## Library notes

- **three.js** is a good fit: lightweight, vanilla-JS friendly and importable via an import map.
  Babylon.js is the main alternative if you want an all-in-one engine with built-in Havok physics.
- **cannon-es** was chosen because it is pure JS, easy to debug and has cone-twist constraints suited to
  ragdolls. Two quirks are handled in [`physics.js`](public/js/sim/physics.js):
  - cannon-es clamps friction *impulses* with a *force* limit, so friction is ~1/Δt too strong (ragdolls
    stick to icy slopes). `world.frictionGravity` is rescaled per physics mode to calibrate it.
  - There is no continuous collision detection, so fast projectiles use a small raycast-based CCD pass, which
    also wakes sleeping bodies just before impact (sleeping bodies are immovable during the step they're hit).
  - Friction is limited by each body's *own* mass rather than the load on it, so the balancing human's light
    feet use a high-grip `shoe` material while standing (switched back to normal grip when it goes limp).
- **Rapier** (`@dimforge/rapier3d-compat`, WASM) is the natural upgrade path if you need larger scenes:
  it is faster, has proper friction and CCD, at the cost of an async WASM init and a less JS-native API.
